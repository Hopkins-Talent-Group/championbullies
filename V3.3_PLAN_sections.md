# v3.3 Plan: Missing Homepage Sections

## Objective

Restore the homepage sections the WordPress site had that the Next.js rebuild
never carried over, so `championbullies.com` and the Next build say the same
thing in the same order.

## How the gap was found

`championbullies.com` currently returns **HTTP 404**, so the live page was read
from the local WordPress mirror (`cb-wp/index.html`, Elementor page id 8, last
modified 2026-09-15 per `wp-json/wp/v2/pages/8`). The Next build was read from
the running deployment at `championbullies.vercel.app`, which matched the repo
exactly at the time of the audit.

## Copy rule

Nothing in `content.ts` is invented. Every sentence is either:

1. **verbatim from the WordPress page** — the four differentiators, the whole
   About story, the trust tagline, the Treasure Cay offer; or
2. **verbatim from the reservation code** — the health guarantee, the
   spay/neuter contract, and the `$500` deposit wording come from
   `Step4-Agreement.tsx`, and the deposit amount is imported from
   `lib/site.ts` rather than retyped.

FAQ answers were only written where the answer was already established by (1)
or (2). No testimonial or statistics section was added, because there is no
verifiable evidence for one.

## Blocked — needs Keith before shipping

1. **The Treasure Cay offer is live copy with a date on it.** It is reproduced
   verbatim from the WordPress page and the page was edited on 2026-09-15, so
   it looks current, but a promo is a promise: confirm it is still valid.
   The offer band is a single component (`Announcement`) and one object
   (`ANNOUNCEMENT` in `content.ts`), so pulling it is a two-line change.
2. **The promo image is not in `public/`.** The WordPress announcement carried
   an uploaded image. The band was built typographically rather than
   referencing a file that would 404. Drop the image into
   `public/images/branding/` to add it.
3. **"From Our Home to Yours" was not rebuilt as a photo band.** The WordPress
   version showed Blue Angel, Lolita, Margo, and Agnes. Blue Angel and Lolita
   are *available* puppies in `PUPPY_CATALOG`, so repeating them in a
   retrospective band would contradict the gallery, and the local
   `puppy-2019.jpg` cannot be confirmed as Agnes. Needs a decision: is that
   band about the parents, past litters, or the family?
4. **All eight catalog prices are the placeholder string `"..."`.** Every card
   and the reservation summary render it literally (`Gallery.tsx:76`). No
   pricing copy can be written until real numbers arrive.
5. **Scrappy's gender disagrees with the plan.** `lib/site.ts` says `Male`;
   `V3.2_PLAN_for_oc.md` calls Scrappy female (Task 4).
6. **Which nav is canonical?** `page.tsx` renders its own inline header.
   `Navigation.tsx` is imported nowhere — verified, zero references in
   `src/app` or `src/components`. It was still updated so it cannot drift, but
   one of the two should be deleted.

## Deliberately not done

- **No testimonials section.** `.github/skills/antislop/SKILL.md` C-5 forbids
  presenting unverifiable proof as fact.
- **No `/puppies/[key]` detail pages.** Every puppy is still a gallery card
  plus a modal. Worth doing, but it is a routing change, not a section.
- **`sitemap.ts` untouched.** The new anchors are fragments of `/`, not
  separate URLs, and listing fragment URLs risks Search Console noise. The
  sitemap already declares `/` with `priority: 1`, which covers them.
- **`metadataBase` still points at the Vercel URL**, because
  `championbullies.com` currently serves 404 and pointing Open Graph at a dead
  domain would break every share card. Switch it when the domain resolves.
